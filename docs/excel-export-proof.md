# בדיקת הוכחה: ייצוא שדות לתאי Excel

**תאריך:** 18.11.2026 · **סטטוס:** בדיקת QA על נתונים סינתטיים בלבד (ללא גישה למסד הייצור).

**תהליך שחזור:** [Excel Mapping Proof ב־GitHub Actions](https://github.com/BIU-Racing/document-system/actions/workflows/excel-mapping-proof.yml) · **סקריפט:** [prove-excel-export.cjs](../scripts/prove-excel-export.cjs).

## מה באמת הוכח?

הסקריפט בונה תשובות דמה לכל שדה שנראה ניתן לכתיבה, מפעיל את מנוע הייצוא האמיתי, מפיק קובצי XLSX/XLSM, קורא בחזרה את תא היעד מתוך XML שבתוך הקובץ, ומשווה את הערך ואת הכתובת למיפוי. נוסחאות או תאים חסרים לא נספרים כהצלחה. בנוסף נבדק ששאר רכיבי קובץ ZIP שלא סומנו כשונו נשמרו ללא שינוי.

| מסמך | רשומות מיפוי | כתיבה פיזית שאומתה | מיפוי ידני במפורש | אחרות |
| --- | ---: | ---: | ---: | ---: |
| ESF | 272 | 222 | 4 | 46 |
| ASES | 453 | 318 | 19 | 116 |
| סה״כ | 725 | 540 | 23 | 162 |

**540 התאמות פיזיות** אומתו גם בבדיקת Python נפרדת שפתחה את קובצי ה־Excel ובדקה כתובות וערכים ב־XML. לא נמצאו אי־התאמות באותן 540 התאמות.

**23 מיפויים** החזירו סטטוס `manual_mapping`, ולכן לא נכתבו אוטומטית: 4 עמודות של טבלת מקטעי המצבר ב־ESF ו־19 בקרות ב־ASES, כולל טבלאות כוח/העתקה ואזור תיעוד גרסאות. **162 הרשומות האחרות** אינן במסלול כתיבה אוטומטית בבדיקה הזו; הן כוללות אסמכתאות, שדות מוגבלים ומיפויים אחרים.

## SES

יש 68 שדות בסך הכול, מהם 34 שדות אסמכתאות/קבצים שאינם מיועדים לכתיבה כתוכן טקסט רגיל בתא. בשאר השדות המשתמש בוחר כתובת תא מתוך טווח מורשה. בבדיקת ניסיון ראשונה הצלחנו לכתוב לערכים ולתאים בטוחים ב־17 שדות; 17 ניסיונות נוספים לא הוכחו, בעיקר משום שערך הניסיון אינו מקיים את אימות התא או משום שאישור הכתיבה תלוי בלוגיקה של Excel.

**לא נטען שנמצא מיפוי תא קבוע ונכון סמנטית לכל שדה SES.** זאת משימת אפיון נוספת ולא כשל שהבדיקה הנוכחית יכולה לשלול.

## מה הבדיקה *לא* מוכיחה?

- שהמשמעות של השאלה במערכת זהה לכותרת של התא המקורי בתבנית. המיפוי הצפוי נלקח מקוד הפרויקט; הוא אינו מקור מקצועי בלתי תלוי. נדרש אישור מומחה על זוגות שדה/גיליון/תא מתוך התבנית.
- שכל תמונה, גרף, מאקרו או נספח משובץ אוטומטית; מצבי `evidence_required`, `manual_mapping` ו־`restricted` דורשים טיפול מוגדר.
- שמיפוי בגרסאות **ESF 2023, ASES 2026 ו־SES 2026** יתאים בהכרח לגרסאות שיוגשו ל־**Italy 2027**. יש לבדוק דרישות פורמליות עתידיות מול [אתר התבניות של המארגנים](https://docs.formula-ata.it/templates).
- שלאחר שינוי נתוני הקבוצה ב־Supabase או שינוי ממשק התצוגה תתקיים תמיד אותה תוצאה; הבדיקה משתמשת במנוע הייצוא עם נתונים מומצאים ללא חיבור למסד.

## מה מכיל קובץ הראיות שניתן להוריד מתוך GitHub Actions?

- `summary.json` — סיכום מספרי.
- `all-field-results.csv` — כל רשומת מיפוי, שדה, כתובת יעד, ערך בדיקה, ערך שנמצא וסטטוס הבדיקה.
- `ESF-synthetic.xlsx`, `ASES-synthetic.xlsm`, `SES-synthetic.xlsx` (בגרסאות הפעלה שבהן נוצרו) — קובצי ייצוא עם נתוני בדיקה בלבד.

## איך מריצים שוב?

1. פותחים את **Actions → Excel Mapping Proof (Synthetic Data)**.
2. לוחצים **Run workflow** כשהתהליך זמין בענף הראשי.
3. פותחים את הריצה, בודקים ש־**Export synthetic values** הצליח.
4. בתחתית הריצה מורידים את ה־**Artifact** בשם `excel-cell-mapping-proof`.
5. פותחים `all-field-results.csv` ומסננים לפי `proof`. סטטוס PASS פירושו *כתיבה פיזית למקום שהוגדר בקוד*, לא אישור סמנטי של המקום.

## לפני הגשה רשמית

- יש לקבל אישור בכתב של בעלי התפקיד הרלוונטיים על **כל שדה מול כתובת התא וראש העמודה בתבנית**.
- יש לפתור את כל הרשומות עם `manual_mapping` ולהגדיר איך נכללים קבצים וראיות.
- ב־SES צריך להגדיר כתובת יעד מחייבת או בחירה הנדסית מבוקרת, ולא להסתמך רק על טווח חוקי.
- רק לאחר מכן יש לאשר את גרסאות קבצי ההגשה העדכניות, להריץ שוב את הבדיקות ולפתוח את הקבצים ב־Excel המקורי.

## תעודת מיפוי (עדכון 26.11.2026)

הפקודה `npm run mapping:certificate` מפיקה בתיקייה `outputs/mapping-certificate` (שאינה נשמרת ב־Git):

| קובץ | מה הוא מראה |
| --- | --- |
| `ESF-marked.xlsx`, `ASES-marked.xlsm` | ייצוא אמיתי מנתונים סינתטיים. בכל תא טקסט כתוב מספר כמו `#0123`, וכך רואים איזו שאלה נחתה בכל תא |
| `mapping-review.xlsx` | שורה לכל שדה: השאלה בעברית, הכותרת שהתבנית עצמה כותבת ליד התא, התא, ותוצאת הבדיקה. יש גם עמודה ריקה לבדיקה אנושית |
| `summary.json`, `results.json` | המספרים ותוצאה לכל רשומת מיפוי |

**הבדיקה האוטומטית** קוראת את הקובץ שנוצר באופן עצמאי, ומוודאת שני דברים:
- כל שדה שנכתב נמצא בתא שלו ועם הערך שלו.
- **אף תא אחר בחוברת לא השתנה**, פרט לברירות מחדל שהמנוע מדווח שניקה ולתאי זהות הקבוצה.

הבדיקה רצה ב־`npm test` (`tests/mapping-certificate.test.mjs`).

**התאמה בין האתר לייצוא:** הבדיקה `tests/official-location.test.mjs` מוודאת שהרמז "ייכתב לתא" בעורך תואם בדיוק את מה שהייצוא עושה, בכל אחת מ־725 הרשומות.

**מה לא מוכח אוטומטית:** שהתא נכון מבחינה הנדסית. לשם כך משווים בעין את השאלה לכותרת שבתבנית, בעזרת `mapping-review.xlsx`.

## מיפוי קבוע ל־SES (עדכון 26.11.2026)

### תא קבוע לכל קלט
- כל תא קלט בודד בתבנית SES הפך לשאלה עם תא קבוע: **815 שאלות ב־30 גיליונות**.
- הרשימה נוצרת מהתבנית עצמה בפקודה `npm run ses:fields`, והתוצר הוא `data/ses-fixed-fields.json`.
- לכל תא נשמרים הכותרת באנגלית, היחידה, הרשימה הסגורה של התבנית וערך ברירת המחדל.

### תוויות בעברית
- התוויות נמצאות ב־`data/ses-field-curation.json`. **הן הצעה לבדיקה הנדסית.**
- ליד כל שאלה מוצגים תמיד הכותרת המקורית באנגלית והתא.

### שאלות מותנות
- בגיליונות שיש בהם "סוג מבנה" (Tubing only / Composite only / Tubes + composite), שאלות הצינור או החומר המרוכב מוסתרות כשאינן רלוונטיות.
- שאלה מוסתרת לא נספרת כחסרה, והתא שלה נשאר כפי שהוא בתבנית.

### בייצוא
- **מספר** נכתב כמספר בלבד. ערך כמו "25 mm" נדחה.
- **בחירה** חייבת להיות מתוך רשימת התבנית.
- **טקסט בעברית** נכתב רק אחרי תרגום תואם.

### "תאים נוספים"
- טבלאות "תאים נוספים" (כתובת ידנית) נשארו רק לאזורים הגדולים, ואינן חובה.
- כתובת של תא שיש לו שאלה קבועה **נחסמת**.
- שורה שנכתבה בכתובת ידנית מסומנת בבדיקת המוכנות לבדיקה.

### תעודת המיפוי
- תעודת המיפוי כוללת עכשיו גם את `SES-marked.xlsx`.
- הבדיקה האוטומטית דורשת שכל 815 השאלות ייכתבו לתא שלהן, ושאף תא אחר לא ישתנה.
